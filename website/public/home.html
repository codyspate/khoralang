Khora is a statically typed, native-compiled language that makes failures, capabilities, resource lifetimes, and concurrency visible without turning application code into ceremony.

The language should tell the truth

The signature above shows two examples. Khora applies the same principle to concurrency, resources, and memory: important behavior should be visible rather than hidden in convention.

The important parts of a program belong in its model.

01

Capabilities, not hidden globals

External authority appears in with rows, so dependencies are reviewable without manually passing service objects everywhere.

Capabilities → 02

Typed failure without wrapper types

Recoverable errors live in raises rows while the code stays direct. Handle what you mean to handle and propagate the rest.

Typed failure → 03

Structured concurrency by default

Fibers live inside lexical scopes, so cancellation, joining, and cleanup are part of the concurrency model rather than conventions.

Concurrency → 04

Native without ownership ceremony

Khora derives memory-management decisions from ordinary functional code instead of asking application developers to write ownership proofs.

Direct style, functional core

Functional ideas without a monadic surface.

Khora keeps algebraic data types, immutable values, typed effects, row polymorphism, and composable pipelines while presenting them in code that reads like ordinary application logic.
