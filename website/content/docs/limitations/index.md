Khora is pre-release. This page exists so users can tell the difference between a language rule, a supported feature, and unfinished work.

## Toolchain distribution

The compiler is currently built from source for development. Versioned downloadable compiler artifacts and a public installation flow are required before the production release.

## Package ecosystem

Dependencies can be pinned reproducibly to git revisions, but there is not yet a public package registry or broad third-party ecosystem.

## Editor tooling

The language server currently provides diagnostics and hover information. Completion, rename, richer navigation, and other production editor features remain release work.

## Standard-library API docs

The curated Guide, Reference, Cookbook, and deployment documentation are being written now. Per-symbol standard-library documentation will be generated by the planned `khora doc` tool from compiler-resolved declarations and `///` documentation comments.

## HTTP surface

The reference HTTP implementation is intentionally not presented as every protocol feature a mature web framework might provide. Release documentation will list exactly which body encodings, upgrades, HTTP versions, and limits are supported by the shipping version.

## Cross-compilation and WebAssembly

LLVM object/module emission is further along than the complete runtime/link/sysroot/deployment path for every target. Only targets tested end to end will be labeled supported.

## Stability

Khora has not reached 1.0. The production release will publish an explicit compatibility policy and migration notes for breaking changes. Until then, source compatibility across arbitrary development revisions is not promised.

## Reporting a limitation

If documentation says something should work and the compiler disagrees, treat that as a bug in either the implementation or the docs. Public examples are expected to become compiler-checked so these two sources cannot drift silently.
