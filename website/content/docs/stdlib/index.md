The Khora standard library is written primarily in Khora and ships with the compiler toolchain. It provides the stable vocabulary and cross-package contracts that ordinary programs need without turning every database, telemetry backend, or platform integration into `std`.

## Major areas

The current standard library includes APIs for:

- strings and collections;
- JSON encoding and decoding;
- files and processes;
- randomness and clocks;
- civil dates and offsets;
- exact `Decimal` arithmetic;
- HTTP client/server building blocks;
- TLS;
- structured concurrency and shared state;
- database capability and row/cell vocabulary;
- tracing context and W3C propagation vocabulary.

## What belongs in `std`

Khora keeps shared contracts in the standard library and leaves fast-moving implementations in packages. For example, `Db`, transaction semantics, and database cell types belong in `std`; PostgreSQL, SQLite, and Cloudflare D1 drivers do not. Trace vocabulary and propagation belong in `std`; vendor exporters do not.

The same principle keeps the IANA time-zone database out of the compatibility promise while retaining stable date/time/offset types.

## Generated API reference

This page is the curated entry point. Per-symbol API pages will be generated by `khora doc --stdlib` from the exact compiler/std revision being documented.

Until automatic documentation generation lands, use the Guide and Cookbook for public concepts and the `std/` source tree for exact current declarations. The production release gate requires generated or compiler-validated API documentation so users are not expected to read source as documentation.
