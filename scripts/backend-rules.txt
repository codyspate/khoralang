# Every way `khora-codegen-llvm`'s lowering can refuse a program.
#
# `scripts/check-backend-rules.sh` fails when this list and the code disagree.
# The list is not documentation -- it is the place a question gets asked, once
# per message: **can a program that passes `khora check` reach this?**
#
#   - If it can, the rule is a *language* rule and belongs in `khora-types`,
#     because the editor publishes what the checker says and nothing from here.
#     The backend then keeps its copy as an assertion about what reaches it.
#   - If it cannot, it is a statement about the compiler -- an operation the
#     backend does not implement, a shape the checker should already have
#     refused -- and belongs exactly where it is.
#
# Two rules failed that question and have moved: raising a type no declaration
# names, and an integer literal wider than an `Int`. Both type-checked cleanly
# and were refused at build time, which no editor could show.
#
# Everything below has been read and is the second kind. Most say so in their
# own words: "is not an operation the backend knows", "which is a compiler
# bug", "has no machine type". The arity and shape checks are the checker's job
# and are duplicated here because lowering cannot proceed without the answer --
# a redundant check is the right shape for that, and a *sole* check is not.
